# Инструкции для ИИ-разработчиков проекта Cortex

Добро пожаловать в репозиторий **Cortex** — локального клиента базы знаний на стеке **Tauri v2 + Rust + Svelte**.

## 📌 Методология: Spec-Driven Development (SDD)
Разработка в этом проекте ведется **строго по спецификациям**. Перед любыми изменениями кода ознакомьтесь со спецификациями:
1. `docs/spec/00_VISION_AND_ARCHITECTURE.md` — общая архитектура и принципы.
2. `docs/spec/01_KNOWLEDGE_VAULT_SPEC.md` — работа с файловой системой и хранилищем `~/knowledge/`.
3. `docs/spec/02_CRYPTO_AND_SECRETS_SPEC.md` — криптография (Age + SSH ed25519).
4. `docs/spec/03_TAURI_IPC_SPEC.md` — контракты IPC между Rust и Svelte.
5. `docs/spec/04_FRONTEND_AND_UI_SPEC.md` — архитектура компонентов Svelte и UI.
6. `docs/spec/05_AI_ASSISTANT_SPEC.md` — интеграция с ассистентом и концепция Blind Agent.

---

## 🛠️ Правила для агентов (Coding Standards)

### Rust (src-tauri)
* **Обработка ошибок**: Никаких `unwrap()` или `expect()` в коде, который может упасть при выполнении пользователя. Используйте `Result<T, AppError>` с типизированными ошибками через `thiserror`.
* **Модульность**: Код разделен на модули `vault`, `crypto`, `ipc`, `ai`.
* **Безопасность памяти**: Секреты в расшифрованном виде хранятся в защищенных структурах (`secrecy` crate или очистка памяти `zeroize`).

### Frontend (src / Svelte)
* **TypeScript**: Строгая типизация (`strict: true`), генерация типов для IPC команд.
* **Стилизация**: Tailwind CSS, адаптивный макет с поддержкой темной темы.
* **Компоненты**: Изолированные компоненты, переиспользуемый `SecretPill.svelte`.

### Изменение спецификаций
Если в процессе разработки меняется логика IPC, формата токенов или контрактов — **сначала обновите соответствующую спецификацию в `docs/spec/`**, а затем пишите код.
